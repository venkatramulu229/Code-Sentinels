Security notes

What this prototype uses

Password hashing

Backend passwords are hashed with bcrypt; responses omit password hashes.

JWT authentication

Protected API calls require a signed, expiring bearer token.

Parameterized SQL

SQLite queries bind request values rather than inserting them into SQL text.

Appointment checks

Booking validates patient identity and schedule conflicts on the backend.

Prototype only: Do not enter real patient data. Configure a strong secret, HTTPS, secure token storage, rate limiting, audit logging, encryption at rest, and a privacy/security review before production. This project does not claim HIPAA compliance.
